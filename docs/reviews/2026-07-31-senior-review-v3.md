## 2. 고친 것

### ★ 통과하지만 아무것도 검증하지 않던 테스트 (가장 중요)

```js
return eq(r.kind, 'member') || eq(r.role, 'member') || eq(r.extra, '한나전도회');
```

`eq()`는 성공 시 `true`, 실패 시 **문자열**을 돌려준다. 둘 다 truthy이므로 `||`는 항상
첫 값에서 단락한다 — **2·3번째 단언은 어떤 경우에도 평가되지 않았다.** 같은 형태가
학생 가입 테스트에도 있어 `학년반`과 `active`가 검증된 적이 없었다.

`all(...)` 헬퍼로 대체했다. 되돌리기 검증: `register`가 `active`를 빈 값으로 쓰게 만들면
이제 실패한다(전에는 통과했다).

### ★ 공허했던 «학교 유출» 테스트

시드 학생에 `학교` 값 자체가 없어, 응답에 유출될 값이 애초에 없었다. 값을 넣고,
`getMembers`뿐 아니라 `whoami`·`getAllRecords`·`register` 응답까지 본다
(계약 §2.1은 "**어떤** API 응답에도"라고 썼다).

### ★ 가입 화면에 대한 정적 검사 부재

`renderRegister`/`setKind`는 `el('#reg-kind-…')`·`el('#reg-school-row')`를 무조건 참조하는데,
`el()`은 없으면 `null`을 돌려준다. id가 하나만 어긋나도 TypeError로 화면이 멈추고,
**이 화면은 모든 신규 가입자가 반드시 지나는 유일한 길**이다.
`check-web.mjs`에 REG_KINDS ↔ index.html 양방향 대조 + 학교 토글 대상 검사를 추가했다.

### 누락됐던 회귀 테스트 3건

- 성도가 `kind`/`role`을 위조해 보내도 기도 4액션이 `forbidden` (불변식 1)
- `kindLabel_`이 미지 kind에 throw («학생»으로 위조하지 않음)
- `MEMBERS_성도` 시트가 없는 상태에서 `register(member)`가 시트를 만들며 성공

## 3. 정정한 사실

**계획 §7-15의 «성도가 우리반에서 빠져 100명 용량 전제가 그대로다»는 틀렸다.**
성도의 기록도 같은 `RECORDS_YYYY-MM` 시트에 쌓인다. 「우리반 제외」는 교사 응답의
**행 수**만 줄이고 **시트 크기와 읽는 셀 수는 줄이지 않는다.** 최악 6,200행.
계약 §2.7과 계획서 양쪽에 정정을 남겼다. 배포를 막을 문제는 아니다(월별 분할이
이미 상한을 잡고 있고, 셀 수 테스트가 보는 것은 `setRecord`가 읽는 열 수다).

## 4. 남긴 한계 (전제로 위장하지 않는다)

`getAllPrayers`에는 성도 필터가 **없다.** 성도는 기도를 쓸 수 없으니 새 행이 안 생기지만,
교사가 학생을 성도로 옮기면 학생 시절 기도 행이 남아 교사 화면에 계속 보인다.
코드가 아니라 운영 절차(`docs/ops/06`)로 처리하고, 계약 §4.2에 «알려진 한계»로 적었다.
