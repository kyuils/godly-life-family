## 1. 이 앱이 무엇인가

혜림교회 청소년부 **우리반 학생·학부모**가 매일 경건생활을 기록·점검하고, 담임교사에게
기도를 요청하며, 개혁주의 신앙 자료를 볼 수 있는 휴대폰용 웹앱.

```
web/      정적 프론트엔드 (GitHub Pages, PWA)
gas/      Google Apps Script 백엔드 (Sheets 읽기/쓰기)
scripts/  검증 하네스 + 자료 수집·생성 스크립트
docs/     specs(계약) · ops(설치 문서) · plans(작업 계획)
```

데이터는 담임교사 계정의 Google Sheets에 있고 **누구에게도 공유하지 않는다.**
이 «비공유 + 소유자로 실행» 설정 자체가 요구사항 8(보안)을 성립시킨다.

## 3. ★ 비밀값은 저장소에 없다 (중요)

이 저장소는 **공개(public)** 다. 아래 값은 **커밋하지 않는다.**

| 값 | 어디에 있나 |
|---|---|
| 스프레드시트 ID | Apps Script 스크립트 속성 `SHEET_ID`, 그리고 개인 메모리 |
| 가입 코드 | 스크립트 속성 `REGISTER_CODE` |
| `gas/Setup.gs`의 `SETUP_*` | 저장소에는 `PASTE_...` placeholder. **실제 값은 Apps Script 편집기에만** |

`web/js/config.js`의 `GAS_URL`·`OAUTH_CLIENT_ID`는 브라우저에 노출되는 값이라 커밋해도 된다.

**다른 PC에서 이어 작업할 때**: 코드 작업과 `npm test`는 비밀값 없이 전부 가능하다.
GAS 배포 단계에서만 Apps Script 편집기에 로그인하면 된다.

## 5. 이 프로젝트에서 지켜 온 작업 방식

1. **계획 → 시니어 검토 → 수정 → 승인 → 실행.** 중요·복잡한 작업은 예외 없이.
   `senior-reviewer` 에이전트를 쓴다. 검토는 칭찬이 아니라 결함을 찾는 것이다.
2. **새 검사는 «되돌리면 실제로 실패하는지»(mutation) 확인한 것만 인정한다.**
   이 규칙 덕분에 실제로 여러 번 «잡지 못하는 검사»를 발견했다.
3. **정적 검사는 «존재 확인»일 뿐이라고 정직하게 적는다.** 행동 검증인 척하지 않는다.
4. **계약(`docs/specs/2026-07-30-api-contract.md`)이 단일 기준.** 코드보다 계약을 먼저 고친다.
5. **보안 불변식 1~9(`CLAUDE.md`)는 어떤 이유로도 완화하지 않는다.**

## 6. 실제로 겪은 함정 (다시 밟지 말 것)

| 함정 | 내용 |
|---|---|
| **화면이 안 바뀐다** | `hidden` 속성은 `.cover{display:flex}` 같은 규칙에 밀린다. `[hidden]{display:none !important}` 없으면 세 화면이 이어 붙는다. **이것 때문에 «로그인이 안 된다»는 신고가 나왔다** |
| **카톡에서 로그인 불가** | 카톡 인앱 브라우저는 구글 로그인 창을 다녀오는 사이 페이지를 다시 읽는다 → 메모리의 로그인 정보 소실. 바깥 브라우저로 열게 안내한다(`web/js/inapp.js`) |
| **CRLF에서 검사기가 무력화** | 정규식 `.`은 `\r`을 매칭하지 않는다. `split(/\r?\n/)`로 잘라야 줄 주석이 지워진다. 안 그러면 주석 속 이름이 «코드»로 오인된다 |
| **`Setup.gs` placeholder** | 저장소 값을 그대로 붙여넣으면 실제 값이 지워지고 `setupAll`이 «중단»만 남긴다. **`SETUP_SHEET_ID`만** 채우고 나머지는 `PASTE_...` 그대로 둔다 |
| **명부 열은 끝에만 추가** | 중간에 끼우면 `setupAll` 재실행 시 라벨만 밀려 `active`·`가입시각`·`가입경로`가 어긋나고 **탈퇴 계정이 되살아난다** |
| **GAS 재배포** | 반드시 **배포 관리 → 수정 → 새 버전**. 「새 배포」를 만들면 주소가 바뀌어 앱이 옛 서버를 부른다 |
| **자료 스키마 변경** | `web/data/*`는 cache-first다. 바꾸면 `web/sw.js`의 `BUILD_TAG`를 반드시 올린다 |
| **로그인이 «두 번» 필요해 보인다** | 서버 왕복 3~8초 동안 화면을 바꾸지 않으면 사용자는 실패한 줄 알고 다시 누른다. 느린 비동기 뒤에는 **반드시 먼저 화면을 바꾼다** (v1.4 §8) |
| **파이썬** | 이 PC에서는 `python`은 되고 `python3`는 없다 |

## 8. v1.4.0 — 로그인 흐름 수정 (2026-08-02 신고 2건)

신고 원문:
1. 「로그인을 하면 바로 메인 페이지로 안 넘어가고 다시 로그인 페이지 나온 후에
   다시 로그인 하면 조금 대기 후에 메인 페이지로 넘어가」
2. 「새로고침하면 자동 다시 로그인하라고 뜬다」

**둘 다 «화면에 아무 표시가 없다» + «로그인 정보를 기기에 저장하지 않는다»에서 나온다.**
설계와 근거는 계약 §6.4에 적었다. 요약:

| 신고 | 원인 | 조치 |
|---|---|---|
| ① | 구글 콜백 뒤 서버 왕복 2~4번(실측 회당 1.3~2.0초, 합계 3~8초) 동안 **로그인 화면이 그대로** 남아 «실패»로 읽힌다 | `#screen-loading` 신설. `whoami`를 **부르기 전에** 화면을 바꾼다. `signingIn` 가드로 흐름이 겹쳐 돌지 않게 한다 |
| ② | 토큰이 메모리에만 있어 새로고침·앱 재실행마다 세션이 사라진다 | 구글 `auto_select`로 **저장 없이** 조용히 재로그인. **앱을 켤 때만** 켠다 |

### ★ 아직 사람이 확인해야 하는 것

`npm test`는 «코드가 그렇게 쓰여 있는가»만 본다. **구글이 실제로 자동 로그인을 해 주는지는
정적 검사로 확인할 수 없다.** 배포 후 실기기에서 아래를 직접 해 볼 것:

1. 로그인 → **메인 화면이 바로 뜨는가** (로그인 화면이 다시 보이면 안 된다)
   - 넘어가는 동안 「로그인 중입니다 / 기록을 불러오고 있어요」가 보여야 정상이다
2. 로그인한 상태에서 **새로고침** → 로그인 화면 없이 그대로 들어가지는가
   - 구글이 자동 로그인을 건너뛰는 정상 조건이 있다(승인된 계정 2개 이상,
     **직전 자동 로그인 후 10분 이내**, One Tap 반복 닫기 쿨다운). 그때는 버튼이 남는다
3. **로그아웃 → 새로고침** → **로그인 화면이 떠야 한다.** 자동으로 다시 들어가지면
   공용 휴대폰에서 계정을 끊을 수단이 없어진 것이므로 **즉시 되돌려야 한다**

만약 ①이 여전하면 로그인 화면의 대괄호 코드(예: `[network_error@whoami]`)를 그대로 적어 둘 것 —
그것이 다음 진단의 출발점이다.

### 아직 손대지 않은 것 (확인 후 판단)

**새로고침 직후 로그인 표지가 잠깐 보이는 «깜빡임».** `start()`는 로그인 화면을 먼저 그리고,
그다음에 구글 스크립트가 준비되기를 기다렸다가 `prompt()`를 부른다. 그래서 자동 로그인이
성공하더라도 그 사이 로그인 표지가 잠깐 보인다.

- 실기기에서 **눈에 띄는지 먼저 확인할 것.** 안 띄면 그대로 둔다.
- 띄면: 부팅을 `#screen-loading`으로 시작하고, GIS 준비 완료 시점에 로그인 표지로 내려간다.
  **주의** — GIS 버튼을 `hidden`인 영역에 그리면 폭이 0으로 잡힐 수 있다.
  반드시 «보이게 만든 뒤 그리는» 순서를 지킬 것.

## 8-2. v1.5.0 — 계정 혼선 + 가입 화면 (2026-08-02)

### ★ 근본 결함 — 한 로그인 안에서 계정이 섞였다

미등록 계정으로 로그인했더니 가입 화면이 안 뜨고
「기록을 불러오지 못했습니다. 등록되지 않은 계정입니다. [unauthorized]」가 떴다는 신고.
**재현으로 확인한 원인**:

```
whoami        ← A 계정 토큰  → ok
getMyRecords  ← B 계정 토큰  → unauthorized
```

`api.js`의 `post()`가 **보내는 순간의** 전역 토큰을 읽는데, 구글 콜백이 진행 중인
흐름과 무관하게 그 전역을 갈아끼우기 때문이다. 설계와 규칙은 **계약 §6.5**에 적었다.
핵심은 «세션 세대(epoch)를 흐름 시작 때 잡아 모든 요청에 넘기고, 어긋나면
`api.call`이 **요청을 만들지 않는다**».

> **이 결함은 v1.4.0이 만든 것이 아니다.** 로그인 버튼을 두 번 누르기만 해도 성립한다.
> 다만 v1.4.0의 자동 로그인(`auto_select`)이 콜백을 하나 더 만들어 창을 넓혔다.

### 가입 화면 검토 결과 — 고친 것

| 심각도 | 문제 | 조치 |
|---|---|---|
| 높음 | 분류를 바꿔도 «학년·반» 값이 남아 `자녀이름`·`소속전도회` 열에 저장됨 | `setKind`가 **분류가 바뀔 때만** 가운데 칸을 비운다 |
| 높음 | **가입 성공한 사람에게** 「등록되지 않은 계정입니다」 | `failAfterRegister` 신설 — 「가입은 완료되었습니다」를 먼저 말한다 |
| 중간 | 빈칸 제출 5회로 10분 잠금(전역 20회라 **반 전체가 잠길 수 있음**) | 제출 전 이름·코드 검사 — 서버로 보내지 않는다 |
| 중간 | `already_registered`에서 다음 행동 안내 없음 | 문구에 조치 추가 |
| 중간 | 분류 선택 상태가 화면낭독기에 전달 안 됨 | `role="group"` + `aria-pressed` |
| 낮음 | 오류가 없어도 붉은 빈 상자가 늘 보임 | `.register-error:empty{display:none}` |
| 낮음 | 가입 화면만 오류 코드 미표시 | `[code]` 병기 |
| 낮음 | 가입 화면 세션만료 시 「보관해 두었어요」가 거짓 | 화면별로 문구를 가른다 |
| 잠재 치명 | 가입 시 헤더 검사가 `email` 열을 안 봐서 **이메일 빈 행**이 저장될 수 있었다 | 필수 헤더에 `email`·`이름`·`active` 추가 |

**문구 변경(사용자 요청)**: 「소속 전도회」→**「혜림교회 소속부서」**, 예시 「예: 청년부」.
**시트 열 이름은 `소속전도회` 그대로다** — 이유와 바꾸는 절차는 계약 §2.2b 참조.
**오타로 보고 고치지 말 것.**

### 고치지 않은 것 (보고만 — 요구사항 변경이거나 요청 밖)

- 학부모의 «자녀 이름»을 **필수**로 할지 (지금은 선택). 비워 두면 명부에서
  학부모–자녀 연결이 비어 담임교사가 누구 부모인지 알 수 없다. **요구사항 6의 변경**이라 판단 보류.
- 가입 입력칸을 `<form>`으로 묶기(휴대폰 키보드의 «완료»로 제출), 죽은 CSS 정리,
  `email`에도 `sanitizeCell_` 적용.

### 검토자 에이전트가 잡아낸 것 (v1.5.0에 반영 완료)

구현 뒤 검토자 에이전트가 실행으로 검증했고, **3건을 더 잡았다.** 전부 고쳤다.

| | 문제 | 조치 |
|---|---|---|
| ① 중대 | **`submitRegister`가 세대 보호 밖에 있었다** — 규칙을 세워 놓고 손댄 그 자리에서 어겼다. 가입 요청 도중 다른 계정 자격증명이 오면 가입 흐름이 **남의 토큰으로 요청을 발사**하고 두 흐름이 각자 `renderApp()`까지 달렸다 | `register`와 그 뒤 `loadMyData`에 같은 세대를 넘긴다. `await` 뒤에 세대를 다시 읽지 않는다 |
| ② 중간 | **v1.5.0이 만든 회귀** — `showUnexpected`의 세대 증가가 **무관한 오류 하나로 정상 로그인을 취소**시켰다. v1.4.0이 고친 「두 번 로그인」이 되살아난다 | 흐름을 건드리지 않는다. 대신 오류 문구를 로딩 화면에 띄우고 탈출 버튼을 즉시 내준다 |
| ③ 중간 | 「다시 시도」가 `whoami` 실패(회선 불안정) 뒤 **영구 비활성**으로 죽었다. 새로고침 말고 회복 수단이 없었다 | 성공·실패 양쪽에서 버튼을 푼다 |

셋 다 **브라우저에서 재현 → 수정 확인**을 마쳤다.

### ★ 사람이 확인해야 하는 것

1. **미등록 구글 계정으로 로그인 → 가입 화면이 «첫 시도»에 떠야 한다.**
   (모의 계정으로 학생·성도 모두 확인했지만, 실제 구글 로그인 창은 자동화가 닿지 못한다)
2. 신고가 재현되면, 그 휴대폰에 **명부에 등재된 다른 구글 계정**이 함께 로그인돼
   있는지 확인할 것 — 그것이 이 결함의 전제였다.
3. 세 분류 가입을 실제 계정으로 한 번씩 (`docs/ops/05-test-checklist.md` B절)
