다른 컴퓨터에서 이어 작업할 때 **이 문서 → `CLAUDE.md` → 진행 중인 계획서** 순으로 읽는다.

## 1. 이 앱이 무엇인가

혜림교회 청소년부 **우리반 학생·학부모**가 매일 경건생활을 기록·점검하고, 담임교사에게
기도를 요청하며, 개혁주의 신앙 자료를 볼 수 있는 휴대폰용 웹앱.

```
web/      정적 프론트엔드 (GitHub Pages, PWA)
gas/      Google Apps Script 백엔드 (Sheets 읽기/쓰기)
scripts/  검증 하네스 + 자료 수집·생성 스크립트
docs/     specs(계약) · ops(설치 문서) · plans(작업 계획)
```

데이터는 담임교사 계정의 Google Sheets에 있고 **누구에게도 공유하지 않는다.**
이 «비공유 + 소유자로 실행» 설정 자체가 요구사항 8(보안)을 성립시킨다.

## 3. ★ 비밀값은 저장소에 없다 (중요)

이 저장소는 **공개(public)** 다. 아래 값은 **커밋하지 않는다.**

| 값 | 어디에 있나 |
|---|---|
| 스프레드시트 ID | Apps Script 스크립트 속성 `SHEET_ID`, 그리고 개인 메모리 |
| 가입 코드 | 스크립트 속성 `REGISTER_CODE` |
| `gas/Setup.gs`의 `SETUP_*` | 저장소에는 `PASTE_...` placeholder. **실제 값은 Apps Script 편집기에만** |

`web/js/config.js`의 `GAS_URL`·`OAUTH_CLIENT_ID`는 브라우저에 노출되는 값이라 커밋해도 된다.

**다른 PC에서 이어 작업할 때**: 코드 작업과 `npm test`는 비밀값 없이 전부 가능하다.
GAS 배포 단계에서만 Apps Script 편집기에 로그인하면 된다.

## 4. 개발·검증 방법

```bash
npm test                      # 전체 검증 (이게 통과해야 완료)
node scripts/mock-server.mjs 8788   # 로컬 미리보기 → http://localhost:8788
```

**로컬에서 화면을 보려면** `web/js/config.js`를 임시로 바꾼다:
```js
GAS_URL: '/api',
MOCK: 'teacher@example.com',   // 또는 'student1@example.com'
```
실제 GAS 코드(`gas/*.gs`)가 모의 시트 위에서 그대로 돌아간다.
**커밋 전 반드시 원래대로 되돌린다** — `npm test`가 이를 검사한다.

### 자료 재생성
```bash
node scripts/build-wcf-items.mjs   # 신도게요서 «항» 구조 (멱등)
node scripts/build-creeds.mjs      # 사도신경·니케아 신경 (멱등)
node scripts/fetch-library.mjs     # 원격에서 자료 재수집 (네트워크 필요)
```

## 5. 이 프로젝트에서 지켜 온 작업 방식

1. **계획 → 시니어 검토 → 수정 → 승인 → 실행.** 중요·복잡한 작업은 예외 없이.
   `senior-reviewer` 에이전트를 쓴다. 검토는 칭찬이 아니라 결함을 찾는 것이다.
2. **새 검사는 «되돌리면 실제로 실패하는지»(mutation) 확인한 것만 인정한다.**
   이 규칙 덕분에 실제로 여러 번 «잡지 못하는 검사»를 발견했다.
3. **정적 검사는 «존재 확인»일 뿐이라고 정직하게 적는다.** 행동 검증인 척하지 않는다.
4. **계약(`docs/specs/2026-07-30-api-contract.md`)이 단일 기준.** 코드보다 계약을 먼저 고친다.
5. **보안 불변식 1~9(`CLAUDE.md`)는 어떤 이유로도 완화하지 않는다.**

## 6. 실제로 겪은 함정 (다시 밟지 말 것)

| 함정 | 내용 |
|---|---|
| **화면이 안 바뀐다** | `hidden` 속성은 `.cover{display:flex}` 같은 규칙에 밀린다. `[hidden]{display:none !important}` 없으면 세 화면이 이어 붙는다. **이것 때문에 «로그인이 안 된다»는 신고가 나왔다** |
| **카톡에서 로그인 불가** | 카톡 인앱 브라우저는 구글 로그인 창을 다녀오는 사이 페이지를 다시 읽는다 → 메모리의 로그인 정보 소실. 바깥 브라우저로 열게 안내한다(`web/js/inapp.js`) |
| **CRLF에서 검사기가 무력화** | 정규식 `.`은 `\r`을 매칭하지 않는다. `split(/\r?\n/)`로 잘라야 줄 주석이 지워진다. 안 그러면 주석 속 이름이 «코드»로 오인된다 |
| **`Setup.gs` placeholder** | 저장소 값을 그대로 붙여넣으면 실제 값이 지워지고 `setupAll`이 «중단»만 남긴다. **`SETUP_SHEET_ID`만** 채우고 나머지는 `PASTE_...` 그대로 둔다 |
| **명부 열은 끝에만 추가** | 중간에 끼우면 `setupAll` 재실행 시 라벨만 밀려 `active`·`가입시각`·`가입경로`가 어긋나고 **탈퇴 계정이 되살아난다** |
| **GAS 재배포** | 반드시 **배포 관리 → 수정 → 새 버전**. 「새 배포」를 만들면 주소가 바뀌어 앱이 옛 서버를 부른다 |
| **자료 스키마 변경** | `web/data/*`는 cache-first다. 바꾸면 `web/sw.js`의 `BUILD_TAG`를 반드시 올린다 |
| **파이썬** | 이 PC에서는 `python`은 되고 `python3`는 없다 |

>
> (설계 근거와 대안 검토는 [`docs/plans/2026-07-31-v2-step3-signup.md`](plans/2026-07-31-v2-step3-signup.md) §10)

**계획서: [`docs/plans/2026-07-31-v2-step3-signup.md`](plans/2026-07-31-v2-step3-signup.md) (r3, 검토 2회 + 사후 검토 반영)**

확정된 설계:

| 분류 | kind | 수집 | 쓸 수 있는 것 | 우리반 표시 |
|---|---|---|---|---|
| 우리반 학생 | `student` | 이름·학년반·**학교** | 날주·달력·기도·자료 | ○ |
| 우리반 학부모 | `parent` | 이름·자녀이름 | 날주·달력·기도·자료 | ○ |
| 혜림교회 성도 | `member` | 이름·소속전도회 | 날주·달력·자료 | **✗** |

- 전화번호는 **전 분류에서 제외**(사용자 결정)
- 학교는 **시트에만** 저장하고 앱 응답에 내보내지 않는다
- 만 14세 미만 동의는 담임교사가 **오프라인으로 이미 받았다** → 앱에 고지 UI 없음.
  다만 성도 분류에는 그 동의가 미치지 않아 «성인만» 안내 한 줄을 넣는다

**구현은 계획서 §8 순서대로 마쳤다.** 특히 `web/js/load.js`를 서버 차단보다 먼저 고쳤다 —
이 파일은 모든 사용자에게 무조건 기도 목록을 요청하므로, 순서를 바꿨다면
**성도가 로그인 직후 적재 실패로 앱에 들어오지 못했을 것**이다(검토에서 잡힌 치명 결함).
되돌리면 실패하는 검사로 묶어 두었다.
