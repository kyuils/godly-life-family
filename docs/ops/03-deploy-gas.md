# 03. 서버 올리고 배포하기

앱의 "서버" 역할을 하는 프로그램을 선생님 구글 계정에 올립니다.

## 1. Apps Script 프로젝트 만들기

1. [script.new](https://script.new) 접속
2. 왼쪽 위 **제목 없는 프로젝트** 클릭 → 이름을 `경건생활 서버`로 변경

## 2. 코드 파일 5개 넣기

기본으로 `코드.gs` 파일 하나가 열려 있습니다. 아래 순서대로 진행합니다.

### 2-1. 첫 파일

1. `코드.gs` 안의 내용을 **전부 지웁니다** (Ctrl+A → Delete)
2. 저장소의 `gas/Sheet.gs` 파일을 열어 **전체 복사** → 붙여넣기
3. 왼쪽 파일 목록에서 `코드.gs` 옆 **⋮** → **이름 바꾸기** → `Sheet` 로 변경

### 2-2. 나머지 4개

왼쪽 **파일 +** → **스크립트**를 눌러 새 파일을 만들고, 이름과 내용을 아래대로 넣습니다.

| 파일 이름 | 붙여넣을 저장소 파일 |
|---|---|
| `Auth` | `gas/Auth.gs` |
| `Actions` | `gas/Actions.gs` |
| `Code` | `gas/Code.gs` |
| `Setup` | `gas/Setup.gs` |

> 이름 입력란에 `.gs`는 안 붙여도 자동으로 붙습니다.
> **파일 순서는 상관없습니다.** 어떤 순서로 넣어도 동작하도록 만들어 두었습니다.

### 2-3. 설정 파일 보이게 하기

1. 왼쪽 **⚙ 프로젝트 설정** 클릭
2. **"appsscript.json" 매니페스트 파일을 편집기에 표시** 체크
3. 왼쪽 **편집기**로 돌아오면 `appsscript.json` 파일이 보입니다
4. 내용을 전부 지우고 저장소의 `gas/appsscript.json` 내용을 붙여넣습니다

   > 이 파일에는 배포 화면의 **기본값 힌트**가 들어 있습니다.
   > 다만 **실제 배포 권한을 결정하는 것은 5번의 배포 대화상자 선택**입니다.
   > 매니페스트만으로는 보장되지 않으니 5번을 반드시 확인하세요.

## 3. Setup 파일에 값 채우기

`Setup.gs`를 열어 맨 위 5줄을 채웁니다.

```javascript
const SETUP_SHEET_ID = '여기에 ① 스프레드시트 ID';
const SETUP_OAUTH_CLIENT_ID = '여기에 ② OAuth 클라이언트 ID';
const SETUP_ADMIN_EMAIL = '선생님 구글 이메일';
const SETUP_ADMIN_NAME = '담임교사';       // 원하는 이름으로
const SETUP_REGISTER_CODE = '여기에 직접 정한 가입 코드';  // 학생들에게 알려줄 코드
```

**가입 코드**는 학생·학부모가 가입할 때 입력할 암호입니다. 아무거나 정하시면 됩니다.
(대소문자·띄어쓰기는 무시됩니다. 저장소가 공개라면 **여기에 실제 코드를 남기지 말고**,
03-5 배포 후 스크립트 속성에서만 설정하세요 — [06번 문서](06-operations.md) 참고)

💾 **Ctrl+S로 저장**합니다.

## 4. 초기 설정 실행

1. 편집기 위쪽 함수 선택 드롭다운에서 **`setupAll`** 선택
2. **▶ 실행** 클릭
3. **처음 한 번은 권한 승인 창이 뜹니다:**
   - "권한 검토" → 선생님 계정 선택
   - **"Google에서 확인하지 않은 앱"** 경고가 뜨면 →
     왼쪽 아래 **고급** → **경건생활 서버(안전하지 않음)으로 이동** 클릭
     > 선생님이 직접 만든 코드라 구글이 아직 심사하지 않았다는 뜻입니다. 정상입니다.
   - **허용**
4. 아래 실행 로그에 **`SETUP COMPLETE`** 가 나오면 성공입니다.

이제 스프레드시트를 열어보면 탭 5개(`MEMBERS_학생`, `MEMBERS_학부모`, `MEMBERS_성도`, `MEMBERS_교사`, `PRAYERS`)가
생겼고, `MEMBERS_교사`에 선생님 계정이 admin으로 등록되어 있습니다.

## 5. 웹앱으로 배포 ★ (가장 중요)

1. 오른쪽 위 **배포** → **새 배포**
2. 왼쪽 **⚙ 유형 선택** → **웹 앱**
3. 설정을 **정확히** 이렇게:

   | 항목 | 값 |
   |---|---|
   | 설명 | `v1` |
   | **다음 사용자 인증 정보로 실행** | **나 (선생님 이메일)** |
   | **액세스 권한이 있는 사용자** | **모든 사용자** |

   > ### ⚠️ 이 두 줄이 이 앱 보안의 전부입니다
   >
   > **"나로 실행"** = 시트는 선생님 권한으로만 열립니다. 학생에게 시트 권한이 필요 없습니다.
   > **"모든 사용자"** = 누구나 앱에 접속은 할 수 있지만, 서버가 로그인을 확인하고
   > **자기 것만** 돌려줍니다.
   >
   > "사용자로 실행"으로 잘못 배포하면 **전원 오류**가 납니다.
   > 그때 고치겠다고 **시트를 공유하면 보안이 완전히 무너집니다.** 배포 설정을 고치세요.

4. **배포** → 나오는 **웹 앱 URL**을 복사해 메모장에 적습니다.

   생김새: `https://script.google.com/macros/s/AKfycb..../exec`

## 6. 잘 올라갔는지 확인

복사한 주소를 브라우저 주소창에 붙여넣고 접속합니다. 아래처럼 나오면 성공입니다.

```json
{"ok":true,"service":"godly-life-family","build":"v1.0.0"}
```

## ③ 웹앱 주소는 어디에 적나 — **저장소가 단일 기준입니다**

예전에는 여기에 주소를 손으로 옮겨 적게 했습니다. 그런데 실제로는 `AKfycb....`
**플레이스홀더가 그대로 남아 있었습니다.** 적히지 않은 값과는 대조할 수 없습니다 —
2026-08-02에 「새 배포」로 주소가 바뀐 것을 아무도 잡지 못한 이유가 바로 이것입니다.

그래서 주소는 **`web/js/config.js`의 `GAS_URL` 한 곳에만** 둡니다.
(브라우저에 공개되는 값이라 커밋해도 됩니다 — `HANDOFF.md` §3)
문서에 사본을 두지 않습니다. **사본은 반드시 낡습니다.**

배포한 뒤에는 눈으로 대조하는 대신 이 명령을 돌리세요:

```bash
node scripts/verify-deploy.mjs
```

앱이 실제로 부르는 주소로 직접 물어보고, 저장소가 기대하는 버전과 대조합니다.

## ★ 나중에 코드를 고쳤을 때 (매우 중요)

**"새 배포"를 다시 만들면 주소가 바뀌어서 앱이 옛날 서버를 계속 부릅니다.**

반드시 이렇게 하세요:

1. **배포** → **배포 관리**
2. 기존 배포 오른쪽 **✏ 연필(수정)** 클릭
3. **버전**을 **새 버전**으로 변경
4. **배포**

주소는 그대로 유지되고 코드만 갱신됩니다.

---

## 이럴 때는

**`setupAll` 실행 시 빨간 오류 — "잘못된 인수입니다" / "Invalid argument: id" 류**
→ `SETUP_SHEET_ID`가 아직 `PASTE_SHEET_ID_HERE`이거나 시트 ID를 잘못 붙여넣었습니다.
   02번 문서에서 `/d/` 와 `/edit` **사이의 문자열만** 복사했는지 확인하고 다시 실행하세요.
   (실행 로그 위쪽에 `!! SHEET_ID가 placeholder입니다` 안내도 함께 나옵니다)

**실행 로그에 "!! OAUTH_CLIENT_ID가 placeholder입니다"**
→ 01번 문서의 클라이언트 ID를 아직 안 넣었습니다. 넣고 `setupAll`을 다시 실행하세요.
   (여러 번 실행해도 안전합니다)

**로그인은 되는데 "구글 로그인 키가 서버와 앱에서 서로 다릅니다"가 떠요** ★
→ 클라이언트 ID를 **두 곳에 붙여넣는데 값이 서로 다릅니다.** 가장 흔한 설치 실수입니다.
   - 서버: 이 문서 3번의 `SETUP_OAUTH_CLIENT_ID`
   - 앱: [04번 문서](04-deploy-web.md) 1번의 `OAUTH_CLIENT_ID`

   두 값을 나란히 놓고 **글자 하나까지 같은지** 확인하세요. 흔한 원인:
   앞뒤 공백이 딸려 붙음 / 「클라이언트 보안 비밀번호」를 잘못 붙여넣음
   (클라이언트 ID는 반드시 `.apps.googleusercontent.com` 으로 끝납니다).
   고친 뒤 서버는 **배포 관리 → 수정 → 새 버전**, 앱은 push 해야 반영됩니다.

**웹앱 주소에 접속했는데 로그인 화면이 나와요**
→ 5번의 "액세스 권한이 있는 사용자"가 **모든 사용자**가 아닙니다. 배포 관리에서 고치세요.

**매달 RECORDS 탭이 새로 생기는데 보호를 다시 걸어야 하나요?**
→ 편집기에서 함수 `protectDataSheets` 를 선택하고 ▶ 실행하면 됩니다.
   분기에 한 번 정도만 해주면 충분합니다.
