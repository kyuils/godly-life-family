# 06. 평소 운영

설치가 끝난 뒤 선생님이 하시게 될 일들입니다.

## 새 학생·학부모 받기

앱 주소와 **가입 코드**만 알려주면 본인이 직접 가입합니다. 선생님이 할 일은 없습니다.

## 가입 코드 바꾸기 / 가입 닫기

가입 기간이 끝나면 **코드를 지워서 가입을 막는 것**을 권합니다.
그러지 않으면 코드를 아는 사람은 언제든 가입할 수 있습니다.

1. [script.google.com](https://script.google.com) → `경건생활 서버` 열기
2. 왼쪽 **⚙ 프로젝트 설정** → 아래쪽 **스크립트 속성**
3. `REGISTER_CODE` 항목의 **✏ 수정**
   - **가입 닫기**: 값을 **완전히 비움** → 저장
   - **코드 변경**: 새 코드 입력 → 저장

가입이 닫히면 새 사람에게 "지금은 가입을 받지 않습니다"라고 안내됩니다.
새 학생이 오면 잠깐 코드를 다시 넣었다가 가입 후 다시 비우시면 됩니다.

## 누구를 교사(관리자)로 만들기

**앱에서는 절대 교사가 될 수 없습니다.** 시트를 직접 고쳐야만 합니다. (일부러 그렇게 만들었습니다)

1. 스프레드시트 → `MEMBERS_교사` 탭
2. 맨 아래에 한 줄 추가:

   | email | 이름 | 역할 | active | 가입시각 |
   |---|---|---|---|---|
   | `sample@gmail.com` | 이교사 | `teacher` | `TRUE` | `2026-08-01` |

3. 그 사람이 이미 `MEMBERS_학생`이나 `MEMBERS_학부모`에도 있으면 **교사가 우선**입니다.

> 반영에 최대 **1분** 걸립니다(성능을 위해 잠시 기억해 둡니다). 바로 안 되면 1분 뒤 새로고침하세요.

## 사용을 중지시키기 (전학·졸업·문제 발생)

해당 명부 탭에서 그 사람의 **`active`** 칸을 `FALSE`로 바꿉니다.

- 즉시 로그인이 막힙니다 (최대 1분 지연).
- 기록은 그대로 남습니다.
- **다시 가입할 수 없습니다** — 되살리려면 `active`를 다시 `TRUE`로 바꾸세요.

## 탈퇴·데이터 삭제 요청

앱에는 탈퇴 기능이 없습니다. 요청이 오면 수동으로 처리합니다.

1. 명부의 `active`를 `FALSE`로 (위와 동일)
2. 기록까지 지워달라고 하면:
   - `RECORDS_*` 탭들과 `PRAYERS` 탭에서 **필터 보기**로 그 이메일을 찾아 해당 줄 삭제
   - ⚠️ **반드시 아무도 앱을 안 쓰는 시간대(예: 새벽)에** 하세요.
     사용 중에 줄을 지우면 다른 사람 기록이 어긋날 수 있습니다.

## 매달 생기는 새 탭

`RECORDS_2026-08` 처럼 매달 자동으로 생깁니다. 선생님이 할 일은 없습니다.

다만 **분기에 한 번쯤** 새 탭에 보호를 걸어주면 좋습니다:
Apps Script 편집기 → 함수 `protectDataSheets` 선택 → ▶ 실행

## 코드를 고쳤을 때 배포하는 법

**서버(gas 폴더)를 고쳤으면:**
1. Apps Script 편집기에 붙여넣고 저장
2. **배포 → 배포 관리 → ✏ 수정 → 버전: 새 버전 → 배포**
   > ⚠️ "새 배포"를 만들면 주소가 바뀌어 앱이 옛 서버를 계속 부릅니다.
3. 웹앱 주소에 접속해 `build` 값이 바뀌었는지 확인

**화면(web 폴더)을 고쳤으면:**
1. `git push`
2. 1~2분 뒤 반영 — 앱 코드는 인터넷에 연결되어 있으면 자동으로 최신이 됩니다.

**참고자료(web/data 폴더)를 바꿨으면 한 단계 더:**
1. `web/sw.js`의 `BUILD_TAG` 값을 올림 (예: `v1.0.1` → `v1.0.2`)
2. `git push`
   > 참고자료는 기기에 저장해 두기 때문에, 이 값을 올려야 새 자료를 받아옵니다.

**고치기 전에 반드시:**
```bash
npm test
```
전부 통과해야 합니다. 특히 보안 관련 검사가 실패하면 **배포하지 마세요.**

## 자주 받는 질문

**"기록이 안 보여요"**
→ 다른 구글 계정으로 로그인했을 가능성이 큽니다. 로그아웃 후 원래 계정으로 로그인.

**"저장이 안 돼요 / 잠시 후 다시 시도하래요"**
→ 저녁에 여러 명이 동시에 저장하면 잠깐 밀립니다. 잠시 뒤 다시 누르면 됩니다.
   자주 그러면 선생님이 시트를 열어 정렬하고 있지 않은지 확인하세요.

**"어제 것을 기록하고 싶어요"**
→ «오늘» 탭 위쪽 «어제 기록하기»를 누르면 됩니다. **그제 이전은 수정할 수 없습니다.**

**"제 기도를 선생님이 보시나요?"**
→ 네, 담임교사만 봅니다. 다른 학생·학부모는 볼 수 없습니다.
   응답 체크는 본인만 할 수 있습니다.

**"가족이 폰을 같이 쓰는데 괜찮나요?"**
→ 네. 계정을 바꾸면 앞사람 데이터가 즉시 지워지도록 만들었습니다.
   그래도 다 쓰신 뒤 **로그아웃**을 눌러주시면 가장 안전합니다.

## 가입 분류 3가지 (2026-07-31 추가)

가입할 때 본인이 셋 중 하나를 고릅니다. 명부 시트도 따로 갈립니다.

| 분류 | 들어가는 시트 | 받는 정보 | 쓸 수 있는 것 | 우리반에 보임 |
|---|---|---|---|---|
| 우리반 학생 | `MEMBERS_학생` | 이름·학년반·학교 | 날주·달력·기도·자료 | 보임 |
| 우리반 학부모 | `MEMBERS_학부모` | 이름·자녀이름 | 날주·달력·기도·자료 | 보임 |
| 혜림교회 성도 | `MEMBERS_성도` | 이름·소속전도회 | 날주·달력·자료 | **안 보임** |

- **성도는 기도 요청을 쓸 수 없습니다.** 교회 성도 전체의 기도가 선생님 한 분께
  모이지 않도록 한 결정입니다. 성도 화면에는 기도 탭이 아예 나타나지 않습니다.
- **학교는 시트에만 저장됩니다.** 앱 화면 어디에도 나오지 않습니다.
- **전화번호는 어느 분류에서도 받지 않습니다.**

### 분류를 옮기려면 (예: 성도 → 우리반 학생)

앱에는 분류를 바꾸는 기능이 없습니다. 시트에서 직접 옮기세요.

1. 원래 시트(`MEMBERS_성도`)에서 그 사람 행의 `active`를 **`FALSE`** 로 바꿉니다.
2. 새 시트(`MEMBERS_학생`)에 행을 추가합니다.
   `email`은 **똑같이**, `active`는 `TRUE`, `가입경로`는 `manual` 로 적으세요.
3. 1분 안에 반영됩니다(명부는 60초 캐시).

> 두 시트에 **둘 다 `TRUE`** 로 두지 마세요. 그러면 우선순위 규칙에 따라
> 한쪽만 적용되어 헷갈립니다. 옮길 때는 반드시 원래 행을 `FALSE`로 바꾸세요.

**우리반 → 성도로 옮길 때는 기도도 함께 정리하세요.**
그 사람이 우리반 시절에 쓴 기도는 `PRAYERS` 시트에 남아 있고, 선생님의 «우리반 →
기도제목» 화면에 **계속 보입니다.** 다른 사람에게 새는 것은 아니지만, 이미 우리반이
아닌 사람의 기도가 남아 있는 셈입니다.

1. `PRAYERS` 시트를 엽니다.
2. **필터 보기**(데이터 → 필터 보기 → 새 필터 보기)로 `email` 열에서 그 사람을 찾습니다.
   일반 필터·정렬은 실제 행 순서를 바꾸므로 쓰지 마세요.
3. 해당 행들의 `삭제여부` 열에 **`TRUE`** 를 적습니다. 행을 지우지는 마세요.
4. 필터 보기를 닫습니다.

### 가입 코드 관리

코드 하나를 세 분류가 함께 씁니다. 대상이 교회 전체로 넓어졌으니 **가끔 바꾸세요.**

1. Apps Script → **프로젝트 설정**(⚙) → 아래 **스크립트 속성**
2. `REGISTER_CODE` 값을 새 코드로 수정 → 저장
3. 새 코드를 알려야 할 분들에게만 전달

**가입 기간이 끝나면 값을 비워 두세요.** 그러면 아무도 새로 가입할 수 없습니다
(이미 가입한 분들은 그대로 쓸 수 있습니다).

### 성도 명부 점검

성도 분류는 **성인(만 14세 이상)** 을 전제로 합니다. 가입 화면에도 그렇게 적어
두었지만, 가끔 `MEMBERS_성도` 시트를 열어 청소년이 잘못 가입하지 않았는지
확인해 주세요. 있으면 위 «분류를 옮기려면» 절차로 옮기시면 됩니다.

## «서버 설정이 완료되지 않았습니다» 가 뜰 때

같은 문구지만 원인이 둘입니다. **Apps Script → 실행 기록**에서 로그를 보면 구분됩니다.

| 로그에 보이는 것 | 원인 | 조치 |
|---|---|---|
| `[auth]` 로 시작 | 구글 로그인 키가 설정되지 않음 | [01번 문서](01-setup-google-cloud.md)의 클라이언트 ID를 다시 확인 |
| `[register] 시트 열 누락` | 명부 시트에 새 열이 아직 없음 | Apps Script에서 **`setupAll` 실행** 후 다시 시도 |

## 특정 한 사람만 «일시적인 오류»로 저장이 안 될 때

로그인은 되는데 **그 사람만** 날주 저장·기도 등록이 계속 실패한다면, 명부 시트 구성이
어긋난 경우입니다. 앱은 알 수 없는 분류를 만나면 **조용히 «학생»으로 적는 대신
실패시킵니다** — 남의 구분으로 기록이 남는 것보다 낫기 때문입니다.

1. 그 사람의 email을 네 명부 시트(`MEMBERS_학생`·`MEMBERS_학부모`·`MEMBERS_성도`·`MEMBERS_교사`)에서 찾습니다.
2. **두 시트에 `active=TRUE`로 중복**되어 있지 않은지 봅니다. 있으면 하나를 `FALSE`로.
3. 명부 시트 **1행의 이름표**가 바뀌지 않았는지 봅니다. 바뀌었으면 `setupAll`을 실행합니다.
4. 그래도 안 되면 Apps Script → 실행 기록의 오류 메시지를 그대로 남겨 두세요.

## 참고자료에 대해

앱의 «자료» 탭 자료는 대한예수교장로회(합동) 총회 전자자료실과 공개 번역본에서 가져왔습니다.
출처와 저작권 표기는 자료 화면 하단에 항상 표시됩니다.

총회나 번역처에서 요청이 오면 **해당 파일만 지우면 즉시 빠집니다**:
`web/data/` 폴더의 해당 `.json` 파일을 지우고 `index.json`에서 그 항목을 삭제 → push.
