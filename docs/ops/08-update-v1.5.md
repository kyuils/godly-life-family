# 다음에 서버를 올릴 때 쓰는 절차

아래는 **이번에 따랐던 순서**이자, 다음 배포 때 그대로 쓰면 되는 절차입니다.

## 1. 되돌릴 수단 만들기 (건너뛰지 마세요)

1. 스프레드시트를 엽니다
2. **파일 → 사본 만들기** → 이름 뒤에 `백업 2026-08-02` 정도로 적고 저장

무슨 일이 생겨도 이 사본으로 돌아올 수 있습니다.
**이 사본은 아무에게도 공유하지 않습니다.**

## 2. 코드 파일 **3개만** 바꿔 넣기

스프레드시트 → **확장 프로그램 → Apps Script** 로 편집기를 엽니다.

저장소 `gas/` 폴더의 아래 **3개**를, 편집기의 같은 이름 파일에
**전체 선택(Ctrl+A) 후 붙여넣기** 합니다.

| 파일 | 무엇이 바뀌었나 |
|---|---|
| `Actions.gs` | 위 1·2번 수정이 들어 있는 파일 (실제 내용 변경은 여기뿐) |
| `Auth.gs` | 주석만 |
| `Code.gs` | 버전 표시만 (`v1.2.0` → `v1.5.0`) |

### ★ 나머지 3개는 **절대 건드리지 마세요**

| 파일 | 이유 |
|---|---|
| **`Setup.gs`** | **바뀌지 않았습니다. 그리고 붙여넣으면 안 됩니다.** 저장소에는 `PASTE_...` 라는 빈 값이 들어 있어서, 붙여넣는 순간 편집기에 있던 **실제 값이 지워집니다.** |
| `Sheet.gs` | 바뀌지 않았습니다 |
| `appsscript.json` | 바뀌지 않았습니다 |

붙여넣은 뒤 **저장(💾 또는 Ctrl+S)** 합니다.

## 3. 배포하기 — ★ «수정»이지 «새 배포»가 아닙니다

오른쪽 위 **배포 → 배포 관리** 를 누릅니다.

1. 목록에 있는 기존 배포의 **연필 아이콘(✏ 수정)** 을 누릅니다
2. **버전** 칸을 **«새 버전»** 으로 바꿉니다
3. **배포** 를 누릅니다

> ### ⚠ 「새 배포」를 만들면 안 됩니다
> 「새 배포」로 만들면 **주소가 바뀝니다.** 그러면 앱은 계속 **옛 서버**를 부르고,
> 방금 올린 수정이 하나도 반영되지 않습니다. 겉으로는 성공한 것처럼 보이므로
> 원인을 찾기가 매우 어렵습니다.
> 반드시 **배포 관리 → ✏ 수정 → 새 버전** 입니다.

## 4. 확인 — ★ 이 명령 하나면 됩니다

```bash
node scripts/verify-deploy.mjs
```

이 명령이 **앱이 실제로 부르는 주소**(`web/js/config.js`의 `GAS_URL`)로 직접 물어보고,
저장소가 기대하는 버전(`gas/Code.gs`의 `BUILD_TAG`)과 같은지 대조합니다.
어긋나면 무엇이 문제인지와 조치 순서를 그 자리에서 알려 줍니다.

> **★ 2026-08-02에 이 단계가 없어서 사고가 났습니다.**
> 예전 문서는 「`03-deploy-gas.md`에 적어 둔 주소와 대조하라」고 했는데,
> 그 문서의 주소는 `AKfycb....` **플레이스홀더라 대조할 대상이 없었습니다.**
> 실행할 수 없는 확인 단계는 없는 것과 같습니다. 그래서 명령으로 바꿨습니다.

### (참고) 손으로 확인하려면

브라우저 주소창에 **웹앱 주소(`/exec`로 끝나는 것)** 를 그대로 붙여넣고 엽니다.

**이렇게 나오면 성공입니다:**

```
{"ok":true,"service":"godly-life-family","build":"v1.5.0"}
```

| 결과 | 뜻 | 할 일 |
|---|---|---|
| `"build":"v1.5.0"` | 성공 | 끝났습니다 |
| `"build":"v1.2.0"` | 옛 버전이 그대로 | **① 먼저 편집기에서 `Code.gs`를 열어** 위쪽에 `const BUILD_TAG = 'v1.5.0';` 이라고 적혀 있는지 **눈으로 확인**하세요. `'v1.2.0'` 이면 **2번(붙여넣기)부터** 다시. `'v1.5.0'` 이 맞다면 **② 3번을 다시** — «새 배포»를 만들었거나 «새 버전»을 안 고른 것입니다 |
| 구글 로그인 화면이 뜬다 | 배포 설정이 틀어졌다 | 배포 설정을 **«나(소유자)로 실행 / 모든 사용자 접근»** 으로 되돌립니다 |
| 「현재 파일을 열 수 없습니다」 | 구글 쪽 일시적 오류 | **한 번 더 새로고침**하세요. 실측에서 아주 가끔 나고 곧 정상으로 돌아옵니다 |

> **★ 왜 «먼저 `Code.gs`를 확인»인가**
> 옛 버전이 나오는 원인은 둘입니다 — **붙여넣기가 안 됐거나(2번), 배포가 잘못됐거나(3번).**
> 이걸 가르지 않으면 붙여넣기가 안 된 상태에서 3번만 계속 반복하게 됩니다.
> `Code.gs`의 `BUILD_TAG` 한 줄이 그것을 1초 만에 갈라 줍니다.

> `web/sw.js`에도 `BUILD_TAG`가 있지만 그건 **화면 쪽 값(`v1.5.4`)** 이고
> 서버 값과는 **원래 다릅니다.** 서버가 `v1.5.0`인 것이 정상입니다.

## 문제가 생기면

| 증상 | 원인 | 조치 |
|---|---|---|
| 가입할 때 «서버 설정이 완료되지 않았습니다» | 명부 시트의 열 이름이 어긋났다 (새 검사가 잡아낸 것) | 해당 명부 시트 1행의 열 이름을 확인 — `email`·`이름`·`active`와 분류별 열(`학년반`/`자녀이름`/`소속전도회`), 학생은 `학교`까지. 대소문자·앞뒤 공백도 정확해야 합니다 |
| 로그인은 되는데 «등록되지 않은 계정입니다» | 명부에 이메일이 빈 행이 있다 | 명부에서 이메일이 빈 행을 찾아 채우거나 지웁니다 |
| 아무것도 안 바뀐 것 같다 | «새 배포»를 만들었다 | 4번 확인표를 다시 |

되돌리려면 **배포 관리 → ✏ 수정 → 버전을 이전 것으로 선택 → 배포** 하면 됩니다.
